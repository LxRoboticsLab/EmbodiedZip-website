05 / HOW WE MEASURE

Make every comparison count.

The evaluation protocol comes before the performance claim.

01 / ESTABLISH

A faithful baseline

Freeze policy revision, preprocessing, hardware, precision, tasks, action horizon, and control rate before measuring optimizations.

02 / ISOLATE

Understand the contribution

Compare baseline, algorithm-only, engineering-only, and combined configurations. Evaluate sync, async, and RTC separately.

03 / VALIDATE

Keep quality in view

Report episode counts, per-task outcomes, paired seeds, confidence intervals, and a predeclared success-rate tolerance.

04 / REPRODUCE

Publish the full picture

Separate loading, warmup, and steady state. Preserve run manifests, request timelines, episode outcomes, and environment versions.

See protocol details ↗
Evaluation protocol & project status

Latency: report P50/P95/P99 with device synchronization where required. Separate loading, compilation warmup, steady state, and cache hit/miss behavior. Measure observation-to-action delay at the execution endpoint.

Memory: record peak device memory and peak process RSS under matching conditions. Speedup is baseline latency divided by optimized latency. Memory reduction is (baseline peak − optimized peak) / baseline peak.

Quality: freeze tasks, episode counts, paired seeds, statistical methods, and success-rate tolerance before measuring. Report per-task success counts, rate differences, confidence intervals, and failure reasons; offline action replay does not establish closed-loop success.

The repository contains shared data contracts, inference protocols, configuration inspection, a mock synchronous example. Model integrations, optimizations, robot execution, benchmark runners, and measured results are pending.

The configurations and task categories on this website describe a proposed experiment structure. They are not implemented capabilities or published experiments.
